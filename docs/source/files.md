# 파일 형식과 예제

시간축 댓글, 참가자 자료, 컷 작업, 영상 파일은 목적이 다릅니다. 파일을 선택했을 때 무엇이 적용되는지 확인하세요.

**로컬 호환 시간축 JSON·TXT는 ttaem.com에 게시할 필요가 없습니다.** 공개 요약 자동 연결과 로컬 파일 가져오기의 차이, 앱에서 여는 순서는 [요약과 JSON 가져오기](summary.md)를 먼저 읽으세요. D1·D2·Point·예상 구간의 뜻은 별도 [시간축 용어](timeline.md)에서 설명합니다. 이 페이지는 파일의 필드와 제한을 확인하는 참고 문서입니다.

## 평문 TXT

기존 댓글 평문은 TXT로 가져와 미리보기할 수 있습니다. JSON을 작성할 필요는 없습니다. 원문·시각·진단을 확인한 뒤 시간축에 불러옵니다.

## 시간축 JSON 가져오기

댓글은 평문으로 작성합니다. 이 JSON은 분석기·편집 도구가 만든 호환 시간축을 가져오는 교환 형식입니다. 컷 작업 저장 파일, 동영상 파일, 댓글 자동 게시 형식과는 별개입니다.

형식 식별자 `chzzk.comment-timeline`, `version: 1`을 사용합니다. 문서 초안 0.4과 parser 출력 `comment_preview.v2`는 별도 버전입니다. 현재 소비자 후보에서 **미리보기 → 확인 후 시간축에 불러오기**로 사용하며, 파일을 고르기만 해서는 기존 자료를 채택하거나 덮어쓰지 않습니다.

```json
{
  "format": "chzzk.comment-timeline",
  "version": 1,
  "documents": [{
    "name": "가상 게임 목차",
    "aliases": [{"alias": "역할A", "streamer": "가상 방송인 A"}],
    "entries": [
      {"role": "chapter", "depth": 1, "startSec": 0, "endSec": 60, "title": "첫 게임"},
      {"startSec": 10, "title": "첫 만남 (w. 역할A)"},
      {"role": "highlight", "startSec": 20, "endSec": 25, "title": "결정적인 순간"}
    ]
  }]
}
```

| 필드 | 의미·조건 |
|---|---|
| `documents` | 1–100개의 원문 문서. 서로 다른 문서의 부모·구간·별칭을 섞지 않음 |
| 문서 `name` | 선택적 표시 이름; 소비자 표시 한도 120자 |
| `raw` 또는 `entries` | 둘 중 하나. `raw`는 기존 댓글 문자열을 그대로 보존. `entries`는 아래 의미 항목을 권고 Markdown으로 투영 |
| `aliases` | 선택적 문서별 가명 목록, 최대 100개. alias/streamer는 공백만으로 이루어지지 않은 80자 이하 문자열; 줄바꿈·대괄호·꺾쇠·슬래시 금지 |
| 항목 `startSec` | 0 이상의 안전한 정수, VOD 경과초 |
| `endSec` | 선택적 정수, 시작보다 뒤. 영상 범위·역할에 맞는지는 host 길이를 포함한 미리보기에서 확인 |
| `title` | 줄바꿈 없는 1,000자 이하 문자열 |
| `role` | 생략하면 `point`; `chapter`, `memo`, `watch`, `highlight`, `collab_context`. 예상 구간은 아래 현재 버전 제한 확인 |
| `depth` | chapter일 때 1–6; 부모 누락이나 겹침은 일반 댓글과 같은 진단 규칙 적용 |
| 루트 `videoNo` | CHZZK 소비자용 선택적 양의 영상 번호. 지정하면 현재 VOD와 같아야 함; 플랫폼 중립 시간 의미와 별개 |

**현재 0.3.23의 제한:** `entries`에서 `role: "expected_highlight"`를 직접 지정하면 역할 대조 검사가 거부합니다. 예상 구간은 문서 `raw`에 `- 03:00 ~ 03:20 [H?] 검토할 장면`처럼 담으세요. 해석 결과는 하이라이트 역할과 검토 전 후보 상태를 함께 유지합니다. [가상 요약 시간표 예제](../../examples/summary-timeline.json)는 이 경로를 사용합니다.

입력은 250,000자 이하, 문서당 항목 최대 5,000개입니다. 본문·진단·완전성 및 영상 길이 규칙은 [의미 계약](reference.md)을 따릅니다. `point`는 순간이므로 `endSec`를 사용할 수 없습니다. 범위는 `memo` 또는 하이라이트 등 해당 역할로 지정하세요. 소비자는 Markdown으로 투영한 뒤 항목 수·역할·시작·명시한 끝·chapter 깊이가 입력과 같은지 확인합니다. 제목의 다른 타임코드나 구문 때문에 의미가 바뀌면 불러오기를 거부하고 원문 `raw` 사용을 안내합니다. 영상 밖 시간과 부모 구조 진단은 미리보기에서 확인합니다.

생성된 entries 본문에는 원래 자연어 댓글이 존재하지 않습니다. 소비자는 이를 원본 댓글이라고 주장하지 말아야 합니다. 원문 출처가 있으면 `raw`를 사용하세요. 현재 버전은 외부 `parentId`, 채널 URL/ID, 확정 싱크, 임의 실행 코드나 HTML을 가져오지 않습니다. `.txt` 평문 가져오기는 이전 호환 기능으로 유지합니다.

합성 JSON 예제는 [portable-timeline.json](../../examples/portable-timeline.json)입니다. 파일 전체를 임의 댓글에 붙여넣는 사용법은 권하지 않습니다.

## 참가자와 역할 이름 가져오기

참가자를 입력하면 도구가 방송인을 찾고, 기준 영상과 방송 시각이 겹치는 다시보기를 선택합니다. 이름 목록은 검색 단서이며 실제 참여 구간이나 영상 동기화가 확인됐다는 뜻이 아닙니다. 기준 영상은 현재 URL의 다시보기로 고정합니다.

### 한 줄 입력

```text
가상 방송인 A, 탐정=가상 방송인 A, 기자=가상 방송인 B
```

쉼표로 참가자를 나누고 `역할명=방송인`으로 역할·가명을 연결합니다. 같은 방송인을 반복해도 참가자는 하나입니다. 하나의 별칭을 여러 방송인에게 연결하면 입력을 거부합니다. 한 줄 2,000자, 이름 80자, 참가자 1–24명이 현재 소비자 한계입니다. 이 입력은 사용자가 현재 VOD에 지정한 보조 자료입니다. 댓글 안의 `별칭:` 선언은 계속 그 원문 안에 적용하며, 서로 충돌하면 자동 신원 선택을 멈춥니다.

### 참가자 파일

```json
{
  "schema": "chzzk.participant-roster",
  "version": 1,
  "members": [
    {"streamer": "가상 방송인 A"},
    {"streamer": "가상 방송인 B"}
  ],
  "aliases": [
    {"alias": "탐정", "streamer": "가상 방송인 A"},
    {"alias": "기자", "streamer": "가상 방송인 B"}
  ]
}
```

`aliases`는 선택사항이며 선언 대상이 `members`에 있어야 합니다. 파일의 단일 이름에 쉼표·등호·줄바꿈·HTML을 넣지 않습니다. 파일은 한 줄 입력과 같은 신원 검사를 거칩니다. [합성 예제](../../examples/participant-roster.json)를 사용할 수 있습니다. 도구가 명시된 참가자 파일을 선택하면 참가자 자료로 적용합니다. [시간축 JSON](files.md)은 장면 미리보기 후 별도 채택하므로 두 파일의 적용 목적이 다릅니다.

### 기존 Syncher 합방 자료

현재 소비자는 기존 `schemaVersion: 3` 자료도 읽습니다. 최소 `projectId` 문자열과 2–12명의 `people`이 필요합니다. 각 인물은 고유한 `id`, `name`과 `vod.url`을 가지며, `vod.url`은 `https://chzzk.naver.com/video/숫자`입니다. 현재 기준 VOD가 명단에 포함되어야 하고 중복 VOD는 거부합니다. `vod.wallAnchorSec`와 `vod.vodAnchorSec`가 유효하면 차이를 영상 0초의 벽시계 기준으로 사용합니다. `vod.verified: true`는 공급자의 확인 표시이며, 같은 사건이나 실제 음성 싱크를 소비자가 새로 검증한 증거가 아닙니다.

참가자 파일은 이름 검색에 필요한 최소 구조입니다. Syncher 자료는 이미 연결한 VOD와 기준 시각을 전달하는 기존 제품 자료입니다. 컷 작업 JSON과 자동 게시 형식으로 쓰지 않습니다.

### 자동 선택과 보정

유일하게 정확한 이름이 일치하는 채널만 자동 후보로 선택합니다. 모호한 이름은 선택을 요청합니다. 방송 시작·길이로 현재 기준 시각을 포함하는 VOD를 고르며, 방송 재시작으로 나뉜 VOD는 다른 다시보기 목록에서 바꿀 수 있어야 합니다. 겹치는 영상이 없으면 임의로 가까운 영상을 정렬하지 않습니다. 방송 시각에 따른 초벌 정렬과 같은 장면의 개인 시각 보정은 구분합니다. 개인 보정은 기준/비교 VOD 쌍에만 적용하고, 영상 선택과 소리 선택은 독립적으로 제공합니다.
