규격과 검증

다음은 구현자와 고급 사용자를 위한 의미 계약입니다. 예제로 시작하려면 지원 형태를 먼저 읽으세요.

화면에 쓰는 D1·D2·Dn·Point·예상 구간의 뜻은 독립 목차인 시간축 용어에서 설명합니다. 공개 요약과 로컬 JSON의 사용 순서는 요약과 JSON 가져오기, 교환 형식의 필드는 파일 형식과 예제에서 확인하세요.

검증 범위

공개 편집 초안 0.4는 CVA-탬패드 0.3.23 후보를 설명합니다. 문서 정적 검사와 합성 fixture 대조, 실제 제품 사용성, 웹사이트 사용성을 구별합니다. 구체적인 commit·파일 해시·실행 결과는 검증 기록에 남깁니다. 후보 및 이전 검증을 설치본 전체 성공으로 바꾸어 주장하지 않습니다.

제품 parser를 공개 배포하거나 이 사이트에서 댓글을 해석하지 않습니다. 공개 예제는 합성 자료입니다. 타 도구 상호운용성·공식 플랫폼 표준·댓글 게시 성공은 별도 확인 대상입니다.

작성 기준: 2026-10-03, 소비자 CVA-탬패드 0.3.23 후보, 구현 형식 식별자 comment_preview.v2. 문서 버전과 구현 출력 schema는 별개입니다. 확정된 국제/플랫폼 표준이나 전체 변환 기본값을 의미하지 않습니다. 후보의 실제 검증 범위는 검증 기록을 따릅니다.

시간과 항목

시간은 원본 VOD의 경과시간입니다. MM:SS와 H:MM:SS를 사용하며 초는 00–59, 시:분:초의 분도 00–59입니다. 분:초의 분은 59를 넘을 수 있습니다. 60:00은 1시간이고 27:01:02도 유효합니다. 날짜·URL·댓글 ID의 숫자를 무차별로 시간으로 바꾸면 안 됩니다.

권고 기본 입력은 - 02:35 설명입니다. 종료가 없는 point는 순간이며 다음 point까지의 범위를 만들지 않습니다. 구간은 [start,end)이고 end > start여야 합니다. 시작과 끝이 같은 구간, 역순, 영상 밖 시각은 진단 대상입니다. 단순한 숫자 나열이나 같은 시각의 반복을 하나의 항목으로 합치지 않습니다.

제목 깊이 D1–D6와 부모

#에서 ######까지 여섯 단계의 제목 구간을 지원합니다. D3 아래 D4, D4 아래 D5, D5 아래 D6처럼 바로 위 단계가 있어야 시간 부모를 확정합니다. 예를 들어:

TEXT
# 00:00 ~ 20:00 게임
## 01:00 ~ 19:00 첫 세션
### 02:00 ~ 18:00 첫 판
#### 03:00 ~ 17:00 준비
##### 04:00 ~ 16:00 팀 계획
###### 05:00 ~ 15:00 마지막 확인
- 06:00 ⭐ 출발

point는 같은 문서 안에서 가장 가까운 유효한 제목 부모를 가집니다. 화면은 D1–D6의 부모 맥락과 원문을 유지해야 합니다. 깊이를 건너뛴 제목은 누락 부모 진단을 남깁니다. 호환 입력 경로에서 해당 시각을 순간으로 복구할 수 있어도 누락된 시간 구간을 발명하지 않습니다.

시작만 있는 제목의 자동 종료는 다음 같은 단계 또는 상위 제목의 시작, 부모의 종료, 마지막의 영상 종료 중 확인 가능한 가장 이른 경계입니다. 영상 길이가 없거나 본문이 부분 수집됐거나 구조 오류가 있으면 끝이 미확정일 수 있습니다. 명시 종료는 자동 계산으로 덮어쓰지 않습니다. 부분 본문에서 연속 행을 확인한 경우에만 확인된 다음 경계를 사용할 수 있고, 마지막 종료는 여전히 모를 수 있습니다.

  • 붙여넣기의 \-- 목록 escape와 &#x20;/&#32;/&nbsp; 공백은 구조 판정용으로만 정규화합니다.

설명, 떨어진 원본 구간

설명:, 맥락:, 검토 상태:는 직전 항목에 붙는 텍스트입니다. 검토 상태 텍스트가 도구의 승인 권한을 부여하지는 않습니다. 명시 범위 안의 떨어진 원본 구간은 다음처럼 적을 수 있습니다.

TEXT
- 02:00 ~ 08:00 [H] 두 사건
설명: 중간의 대기는 포함하지 않습니다.
원본 구간: 02:00 ~ 03:00; 06:00 ~ 08:00

원본 구간들은 유효하고 정렬돼 있으며 겹치지 않고 바깥 범위 안에 있어야 합니다. 03:00–06:00의 빈 구간을 재생 범위로 채우지 않습니다. 현재 주 항목의 이동 시각은 정수 초, 세부 원본 구간은 최대 밀리초 세 자리까지 읽습니다.

합방 멤버

합방: 이름 A, 이름 B는 직전 제목 구간 또는 [합방] 범위에 명단을 붙입니다. 제목 끝 (합방: 이름 A, 이름 B)도 읽습니다. 함께:와 참여:는 기존 입력 호환 별칭이며 권고 표기는 합방:입니다.

자식 항목은 가장 가까운 명시적 부모 명단을 이어받습니다. 새 독립 D1은 이전 D1 명단을 이어받지 않습니다. 합방: 없음은 명시적으로 멤버가 없다는 뜻, 합방: 미확인은 모른다는 뜻입니다. 누락도 별도 상태입니다. 중복·충돌 명단은 원문과 진단을 보존합니다. 평문 이름 후보는 확정 명단으로 승격하지 않습니다.

이름은 채널 신원이나 영상 offset의 증거가 아닙니다. 구현이 공개 방송 시작 시각과 길이로 겹치는 VOD를 찾더라도 방송 기간 후보 등록과 같은 사건의 정확한 시각 정렬을 구별해야 합니다. 댓글 규격은 CHZZK ID, ttaem URL, 인증 서버를 필수 헤더로 요구하지 않습니다.

불명확한 입력과 긴 댓글

모르는 태그, 시간 없는 안내, 일부 잘못된 시각은 원문·문서·행·진단과 함께 보존합니다. 한 행의 잘못된 시간 때문에 나머지 유효 anchor를 지우지 않습니다. 전체 구조를 확정할 근거가 없으면 순간과 미확정 종료를 분명히 표시합니다. HTML·스크립트·원격 이미지·댓글 속 명령을 실행하지 않습니다.

긴 댓글은 항목과 설명을 통째로 유지하며 필요한 부모 제목·명단·맥락을 각 부분에 반복합니다. 자동 제목 종료는 분할 전에 명시 종료로 고정합니다. 반복한 부모 맥락과 실제 원본 항목을 구분해 항목을 중복 채택하지 않아야 합니다. 한 항목과 부모 맥락이 한 부분의 한도를 넘거나 진단/알 수 없는 종료가 있으면 분할을 실패로 알려야 합니다. 자동 잘라내기나 의미 손실을 성공으로 표시하지 않습니다.

플랫폼 댓글 한도는 adapter가 실제 UI/API의 제한을 확인해 제공합니다. 제품 분할 함수의 기본값 5,000자는 CHZZK의 보장된 공식 최대 길이가 아닙니다. 코드의 JavaScript 문자열 길이(UTF-16 code unit), 입력 미리보기 상한 250,000, 분할 인수 100–250,000도 플랫폼 게시 한도와 별개입니다.

관련 인물과 교환 입력

문서별 가명 연결, with 표기와 명시 참여자의 구별은 관련 인물 계약을 따릅니다. 다른 도구의 chzzk.comment-timeline 버전 1 입력은 교환 형식을 따릅니다. 기존 평문 원문·시간·역할·부모 의미와 채택 snapshot 보존 규칙은 유지합니다.

참가자 검색을 위한 한 줄 입력, chzzk.participant-roster 버전 1과 기존 Syncher 합방 자료는 참가자 가져오기를 따릅니다. 이름·역할·참여 구간·채널·VOD 시각을 하나의 신원 사실로 합치지 않습니다.

강조된 시각과 제목 아래 중첩 목록

**00:03:21**, __00:03:21__ 및 대응되는 한 겹 강조 기호는 시각을 읽을 때만 벗깁니다. 전체 원문과 강조 표시를 삭제하거나 HTML을 실행하지 않습니다. 짧은 제목 아래 단일 - 시각 행이 두 개 이상이고 --/└/ㄴ 하위 시각 행이 있으면, 그 제목을 다음 실제 시각에 연결한 D1, 단일 목록을 D2, 하위 순간을 Point로 추론할 수 있습니다. 특정 게임·방송인 이름 사전을 조건으로 쓰지 않습니다. 명시 역할과 엄격 제목 문법을 우선하며, 근거가 부족한 평평한 목록은 Point를 유지합니다. 추론 근거와 원문/시각 anchor 행을 함께 남겨 수정 가능하게 합니다.

같은 시각, 역순 시각, 작성자 별 표시는 항목 신원이나 계층과 별개입니다. 시각만으로 합치거나 역순 항목을 버리지 않습니다. 부분 원문·알 수 없는 영상 길이·불명확한 경계에서는 D1/D2의 끝을 미확정으로 둡니다. 강조된 중첩 목차 예제는 제목·강조·역순·부분 원문을 함께 대조합니다.

0.4의 명확한 구조와 보수적 확인

명확한 상대 들여쓰기는 전체 시각 목록의 공통여백을 뺀 뒤 판정합니다. 두 칸 이상, 탭, 전각 공백 등 지원하는 명확한 증가에서 주제 D1 아래 장면 D2를 읽고, 그보다 깊은 시각 행은 Point로 유지합니다. 전체 목록의 동일 여백·단일 우연 공백·시간 없는 일반 문장은 부모 구간의 근거가 아닙니다. 이 구조는 추론 근거·원문·anchor 행을 보존하며 명시 제목/역할 규칙보다 우선하지 않습니다.

단독 ■와 단독 Markdown 구분선은 독립 목록 경계입니다. 각 경계에서 앞 주제·부모·명단 맥락을 분리하고 새 목록을 판정합니다. 일반 문장 속 ■와 빈줄은 확정 경계가 아닙니다. 별도로 모은 곡 목록·장면 색인에 앞 목록의 계층을 강제로 붙이지 않습니다. 경계 전 마지막 자동 제목 끝을 뒤 색인의 역순 시각이나 영상 길이로 무조건 완성하지 않습니다.

01:23 시작 (02:55)는 앞 anchor 01:23과 전체 원문을 보존하고 recoverable parenthesized_time_review 안내를 남깁니다. 괄호 속 단독 시각은 참고·정정·실제 시작 등의 의도가 모호하므로 자동 두 번째 anchor나 종료로 바꾸지 않습니다. 여러 순간은 01:23 / 02:55 시작, 범위는 01:23 ~ 02:55 [메모] 시작 구간처럼 명시할 수 있습니다. 대괄호 시각의 호환 규칙을 소괄호 전체로 확장하지 않습니다.

지나치게 큰 수, 소수 주 시각, 잘못된 자리수·분·초 등은 유효 anchor로 확정하지 않습니다. 오류 행의 원문·진단과 유효한 이웃 항목을 보존합니다. 전각 숫자·임의 분류·자유문장·복잡한 Markdown 전체의 지원을 추가하지 않습니다. 혼합 형상 합성 예제는 실제 사용자 댓글을 포함하지 않습니다.
