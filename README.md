# 치지직 댓글로 만드는 Markdown 타임라인

다시보기 댓글에 **영상 경과시간과 설명**을 적으면 사람이 평문으로 읽고, 호환 도구가 같은 시각으로 이동할 수 있습니다. Markdown은 선택사항입니다. 계정 연동, 확장 설치, JSON이나 특정 서버를 알아야 작성할 수 있는 형식이 아닙니다.

이 저장소는 **현재 지원을 설명하는 공개 편집 초안 0.3**입니다. NAVER/CHZZK의 공식 표준이 아니며, 제품 전체 변환의 기본 출력이나 C08 수락을 확정하지 않습니다. 공개 문서 발행, 실제 댓글 게시, 확장 스토어 배포는 서로 다른 일입니다. 여기서는 댓글을 자동 게시하지 않습니다.

## 가장 작은 시작

```text
00:00 방송 시작
02:35 오늘 할 게임 이야기
08:12 다시 보고 싶은 순간
```

한 줄은 하나의 이동 지점입니다. `02:35`는 2분 35초, `1:02:35`는 1시간 2분 35초입니다. 방송 날짜나 벽시계 시각이 아닙니다. 제목 없이 `54:30`만 적어도 책갈피로 읽을 수 있습니다.

## 구간과 중요한 순간을 함께 쓰기

```text
# 00:00 ~ 20:00 인사와 준비
- 02:35 오늘 할 게임 이야기
- 08:12 ⭐ 다시 보고 싶은 순간
## 10:00 ~ 18:30 첫 번째 판
- 12:10 [메모] 앞 대화와 이어서 보기
# 20:00 ~ 30:00 다음 게임
합방: 가상 방송인 A, 가상 방송인 B
- 22:10 첫 사건
```

`#`와 `##`는 이야기 **구간**, `-`는 **한 순간**, `⭐`는 작성자가 강조한 표시입니다. `시작 ~ 끝`으로 범위를 직접 적으면 끝을 추측할 필요가 없습니다. 마지막 예제의 이름은 실제 방송인을 가리키지 않는 합성 이름입니다.

시작만 쓴 제목 구간도 읽을 수 있습니다. 다만 자동 끝은 다음 같은 단계/상위 제목, 부모 끝, 영상 길이와 본문 완전성을 확인해야 계산됩니다. 부분 본문이나 불명확한 경계에서는 끝을 모른다고 표시합니다. 플랫폼이 Markdown을 렌더링하지 않아도 위 댓글은 평문으로 읽을 수 있습니다.

## 기존 주제·게임 목차도 그대로 가져오기

`#`를 다시 입력하지 않아도 주제와 하위 목록이 분명한 댓글은 구조를 읽을 수 있습니다.

```text
00:03:25 방송 시작
00:25:23 운동 이야기
01:49:59 첫 게임 시작
- 02:34:01 지하궁전
- 03:19:15 두 번째 판
--03:20:10 ⭐ 뜻밖의 사건
03:38:34 다음 게임
- 03:40:23 1판
```

이 자연 목차에서는 최상위 행을 **D1 주제**, `-` 행을 **D2 장면**, `--` 행을
**Point 사건**으로 읽습니다. 명시 `#` 문법에서는 `-`가 계속 Point이며, 구조 없는
평면 시각 목록도 순간으로 유지합니다. 원문과 자동 구조를 미리보기에서 확인한 뒤
`시간축에 불러오기` 한 번으로 채택합니다.

시간 없는 분류 제목과 트리 표시도 가능합니다.

```text
💬 저챗
0:03:50 등장
0:06:26 건강 이야기
🎮 두 번째 게임 | 0:17:51
0:17:59 입장
1:42:20 팀 경기
└ 1:50:42 코스 설명
└ 1:59:14 경기 시작
```

`💬 저챗`은 다음 실제 시각 0:03:50부터 시작하는 D1, 분류 아래 시각 행은 D2,
`└` 행은 앞 장면의 Point입니다. 시간 없는 제목에 0초를 만들어 넣지 않습니다.
자동 끝·같은 시각·부분 본문과 추론의 한계는 [의미 계약](SPEC.md#자연-목차의-구조-추론)을 따릅니다.

## 문서와 예제

- [문법과 의미 계약](SPEC.md): D1–D6, 시간, 구간, 부모 맥락, 역할, 합방, 원문과 진단.
- [현재 지원 범위와 한계](SUPPORT.md): 실제 구현이 지원하는 것과 확인되지 않은 것.
- [합성 입력과 기대 의미](examples/fixtures.json): 기존 댓글 표현을 본뜬 공개 안전 예제. 실제 댓글·작성자·계정 자료를 포함하지 않습니다.
- [자연 목차의 합성 예제](examples/natural-hierarchy.json): 주제/판/사건, 분류 제목과 다음 시각, 트리·강조·명시 범위의 역할·부모 연결.
- [검증 기록](VALIDATION.md): 검증한 구현 식별자와 검사 범위. 다른 구현의 호환성 증명과 구별합니다.
- [기여 안내](CONTRIBUTING.md): 입력, 기대 결과, 실제 결과로 차이를 설명하는 방법.

문서·합성 예제는 [MIT 라이선스](LICENSE)를 사용합니다. 이 저장소는 제품 소스나 비공개 개발 이력을 배포하지 않습니다.

## 관련 인물과 도구 간 시간축

`(w. …)`, 가명·방송인 연결과 참여자 구별은 [관련 인물과 가명](PEOPLE.md)에, 다른 도구가 만든 JSON 시간축은 [가져오기 형식](IMPORT.md)에 정리합니다. 댓글을 작성하기 위해 JSON을 만들 필요는 없습니다.
